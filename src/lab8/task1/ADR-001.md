# ADR-001: Архітектурний рефакторинг підсистеми видачі книг бібліотеки за методологією GRASP

## Статус
Прийнято (Accepted)

## Контекст
У вихідному Legacy-коді класу `LegacyLibraryProcessor` виявлено класичні антипатерни:
1. **Anemic Domain Model:** класи `Reader`, `Book`, `LoanRecord` є суто місткостями для даних із відкритими публічними полями (`public fields`), не містять жодних інваріантів чи бізнес-методів.
2. **Bloated Controller / Monolithic God Method:** метод `issueBookFromConsole()` монолітно поєднує введення з консолі (`Scanner`), створення сутностей через пряме заповнення публічних полів, розрахунок тарифів через процедурні розгалуження `if-else`, пряме логування в файл та відправку email.
3. **Порушення Закону Деметри:** клієнтський код використовує навігаційні ланцюжки виду `loan.reader.name`, `loan.book.category`, що веде до високого зачеплення (High Coupling, CBO > 5).

## Рішення
Застосовано патерни GRASP для декомпозиції системи:
1. **Information Expert:** розрахунок підсумкової вартості видачі та перевірка лімітів інкапсульовано безпосередньо в доменну сутність `LoanRecord`. Стан полів захищено модифікаторами `private` та імутабельністю.
2. **Creator:** конструювання об'єкта `LoanRecord` інкапсульовано у фабричний метод або конструктор, що приймає валідні сутності `Reader` та `Book`, гарантуючи валідний стан з моменту створення.
3. **Controller:** виділено тонкий Use-Case контролер `LoanController`, який координує виконання сценарію видачі книги, не містить операцій введення-виведення та взаємодіє з DTO.
4. **Indirection & Pure Fabrication:** створено абстракції сховищ даних (`IBookRepository`, `IReaderRepository`, `ILoanRepository`), сервіс сповіщень `IEmailNotifier`, аудит-логер `IAuditLogger` та окремий CLI-інтерфейс `ConsoleLibraryUI`.

## Наслідки
### Позитивні
* Доменні сутності переведено в стан **Rich Domain Model** із високою згуртованістю (High Cohesion, LCOM4 = 1).
* Знижено зачеплення (Low Coupling): доменні сутності та контролер тепер мають CBO ≤ 4.
* Дотримано принцип Stable Dependencies ($I_{CLI} \rightarrow I_{Application} \rightarrow I_{Domain}$).

### Компроміси
* Збільшення загальної кількості класів та інтерфейсів для дотримання чистої архітектури.
